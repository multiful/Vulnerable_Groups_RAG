## Anti-Patterns Verdict

**LLM assessment (A):** 5 of 7 banned patterns confirmed. The compositional decisions strongly reflect AI layout generation — the eyebrow pattern on 7+ elements and the hero-metric block with "RAG" as a metric slot are the clearest tells. The glassmorphism on the sticky header and mobile nav is pervasive (every page, every scroll). The featured cert card has a surviving side-stripe via inline `borderLeftColor`. The mascot bounce is a double-spring (timing function + keyframe oscillation both encode bounce physics).

## Overall Impression

This is a product built with genuine care for a difficult user population — the crisis safety implementation, session restore, and in-memory caching all reflect domain empathy. But the UI composition decisions undercut that empathy in three specific places: the red color applied to the most vulnerable users at the emotional peak, the invisible CTA that connects assessment results to the actual product value, and an evidence modal that tries to serve five different research workflows simultaneously. Fix those three things and the product's soul would show through more clearly. The eyebrow/metric AI-tell pattern is the cosmetic gap; the red-on-crisis and invisible-CTA are the functional ones.

## What's Working

**1. Crisis safety implementation.** The `safetyKey` flag on Q11, the crisis auto-floor, and the `tel:1393` tappable link — these details reflect real domain knowledge executed correctly. The safety banner appears in correct reading order before the result card.

**2. Recommendation page React architecture.** Ten `useRef` caches (`evidenceCacheRef`, `certExplainCacheRef`, `dagCacheRef`, etc.), `useDeferredValue` for search, `useTransition` for state updates, `fetched` guard flags for API deduplication — all correctly applied for an audience that may be on low-end devices.

**3. Survey UX.** One question per card, category badge for context, 260ms auto-advance for momentum, session persist with restore banner — this is the strongest flow in the product.

## Priority Issues

**[P0] Red color applied to highest-risk users at the peak emotional moment**
- **What**: Stage 4 result color `#f43f5e` is applied to: the stage badge, the progress bar, the radar chart polygon, category bar fills, AND the primary CTA button — creating a fully red result page for the most vulnerable users.
- **Why it matters**: Clinically contra-indicated. A Stage 4 user who may have just disclosed suicidal ideation sees an all-red screen with the label "은둔 청년" in large text. The safety banner also uses red styling — double-red page at the highest-stakes moment. This actively works against emotional safety.
- **Fix**: Assign calming neutrals (deep slate-blue, violet, or indigo) to higher risk stages. Reserve red exclusively for the explicit safety banner. Stage color should reflect the recommended action, not a severity alarm.
- **Suggested command**: `/impeccable harden`

**[P0] "자격증 추천 받기 →" CTA is visually invisible**
- **What**: The funnel's most critical transition button renders with `background: none; border: none; font-size: .8rem; color: var(--text-muted)` — a plain text link in muted gray, placed after two prominently styled primary/ghost buttons.
- **Why it matters**: This is the gateway to the product's value proposition for every user who completes the survey. Burying it as an afterthought means the conversion from assessment to recommendation — the entire product funnel — depends on users noticing a barely-visible text link.
- **Fix**: Render as `btn-primary` or a dedicated callout card with forward framing ("당신에게 맞는 자격증 추천받기 →"). Consider making it the sole CTA after the result summary.
- **Suggested command**: `/impeccable harden`

**[P1] Mobile navigation has no "진단 시작" entry point**
- **What**: The mobile bottom nav has 홈/시험일정/직업탐색/채용행사/훈련. The `header-cta` ("진단 시작") is `display: none` on mobile. The sticky CTA only appears after 420px of scroll on the home page.
- **Why it matters**: The primary action — the product's entire reason to exist — has no persistent entry in the mobile navigation. For an audience that is predominantly mobile, this is a funnel break at the entry point.
- **Fix**: Replace one low-priority mobile nav item (e.g., 채용행사 which requires an active job search intent) with "진단" using a bolt/compass icon.
- **Suggested command**: `/impeccable harden`

**[P1] Evidence modal scope is five workflows in one container**
- **What**: The modal launched by "왜 추천됐나요" contains: AI explanation, DAG relationship diagram, evidence rows, a 4-tab exec panel (시험일정/채용행사/훈련과정/자격증정보), and a video section.
- **Why it matters**: A user asking "왜 추천됐나요?" has a single-question intent. The answer is in the first two sections (AI explanation + evidence rows). The remaining 70% of the modal is a research workspace that requires a different user mindset and session. The cognitive surface overwhelms the answer.
- **Fix**: Split into two surfaces: a focused "추천 이유" modal (AI explanation + top 3 evidence snippets) and a separate cert detail page for the exec data, schedule, training, and videos.
- **Suggested command**: `/impeccable shape`

**[P1] RiskAssessment + Recommendation have zero mobile breakpoints**
- **What**: `@media` queries (excluding `prefers-*`) are absent from both pages' inline style blocks.
- **Why it matters**: The 12-question survey and the 60-cert recommendation grid — the product's complete user flow — break on mobile. Survey answer options have no `min-height: 44px` touch targets. Cert grid collapses to unusable widths. Evidence modal is scroll-within-scroll on small screens.
- **Fix**: Add breakpoints for survey single-column layout and 44px touch targets; cert grid `auto-fit / minmax(280px, 1fr)`; modal `width: 95vw` + `max-height: 95dvh` on mobile.
- **Suggested command**: `/impeccable adapt`

**[P2] Uppercase eyebrow pattern on 7+ elements**
- **What**: `PERSONALIZED / STRUCTURED / EVIDENCE-BACKED` (English, PROMISES section), `.dag-panel-title`, `.policy-classify-label`, `.footer-col-title`, `.ds-label` — all use `text-transform: uppercase; letter-spacing: .05-.08em`.
- **Why it matters**: This is the most visible AI-layout tell. For a Korean-language product serving at-risk youth, English marketing uppercase keywords are tonally inconsistent and aesthetically generic.
- **Fix**: Remove the eyebrow pattern from all sections where it's reflexive. Replace English PROMISES keywords with no label (let the h3 carry the weight) or a Korean numeral (1 · 2 · 3) only where sequence matters.
- **Suggested command**: `/impeccable distill`

**[P2] ~15+ hard-coded hex colors in Recommendation evidence panel break dark mode**
- **What**: Lines 2445–2604 in Recommendation use `#1d4ed8`, `#15803d`, `#92400e`, `#0ea5e9`, `#0c4a6e`, `#bae6fd`, and others directly. B found ~15 instances not using tokens.
- **Why it matters**: Dark mode tokens were seeded in `index.css` but page-level hard-coded colors won't respond. Any dark mode adaptation will produce unreadable combinations.
- **Fix**: Tokenize the semantic sub-palette: `--salary-accent: #0ea5e9`, `--exam-accent: #f59e0b`, `--career-accent: #10b981`, and dark variants. Replace inline hex with `var()`.
- **Suggested command**: `/impeccable colorize`

## Persona Red Flags

**Jordan (confused first-timer):**
- Hero badge uses "청년 위험군" — clinical government taxonomy that a young adult in distress may not self-apply. Risk of disidentification before they engage.
- English PROMISES keywords (`PERSONALIZED`, `STRUCTURED`, `EVIDENCE-BACKED`) and "RAG" as a metric assume literacy the target audience may not have.
- The survey time estimate is absent ("12문항, 약 3분 소요" would help Jordan commit).
- After survey completion, no acknowledgment copy. Jordan navigates a raw stage number and color badge with no emotional preparation.

**Sam (accessibility-dependent):**
- Survey radio indicators use unicode `●` / `○` as visible text — a screen reader may announce "black circle" / "white circle" rather than "selected" / "unselected." These should be `aria-checked` or `role="radio"` with visually-hidden text.
- `--text-muted: #64748b` on `--bg: #f6f8fc` is approximately 4.3:1 — marginally passing AA for large text but failing for the many sub-14px usages (`.82rem`, `.78rem`, `.72rem` throughout).
- `.footer-disclaimer` at `.68rem` (~11px) and multiple badge/chip labels at `.7rem` (~11px) are below practical minimum for low-vision users.
- No `aria-live` regions anywhere for async state changes — loading, success, and error states are all silent to AT.

**Casey (distracted mobile user):**
- 260ms auto-advance on survey tap may register as accidental selection when touching a phone on the move. No undo mechanism.
- Mobile bottom nav labels at `0.64rem` (≈10px) are below legible minimum for glanceable use.
- Evidence modal is scroll-within-scroll at 90vh with sub-sections — one-handed navigation on a small screen is extremely difficult.
- Sub-12px text throughout recommendation and evidence panels is effectively inaccessible on a moving device.

## Minor Observations

- `--secondary` and `--secondary-light` in `index.css` are exact duplicates of `--primary` values — dead tokens indicating copy-paste origin.
- `btn-primary:hover` has two separate rule blocks at lines 143 and 144–148 in `index.css`. The `background: var(--primary-dark)` in the first rule is immediately shadowed and never applies.
- `window.addEventListener` for ESC in MainLayout vs. `document.addEventListener` for ESC in Recommendation — inconsistent event target binding.
- `.promise-card` references `.promise-primary`, `.promise-secondary`, `.promise-accent` class names (Home/index.tsx line 159) not defined in visible CSS — likely dead.
- The `.today-example-card` uses `rgba(255,255,255,.1)` inside the cobalt blue hero section — glassmorphism inside the only full-bleed colored section creates a nested visual effect.
- Roadmap: 5× `transition: all` — safe now but a footgun that will silently animate any future layout property added to those elements.
- IsolationDashboard `.iso-action-card` has `border-left: 4px solid` with no color value — inherits `currentColor`, fragile and implicit.

## Questions to Consider

1. **Is "단계" (stage number) the right output for a vulnerable person?** The product delivers "당신은 3단계: 활동 제한형 고립청년입니다" as the climax of a 12-question emotional disclosure. What would the experience look like if the result screen surfaced only the first recommended action ("지금 당신에게 맞는 첫 번째 자격증은 이것입니다") rather than a bureaucratic classification?

2. **Does showing 60 certification options serve the mission?** An at-risk user who can't decide between 60 options is in a worse position than one who had no recommendation. What would 3 curated picks with explicit reasoning look like — with "더 보기" for users who want to explore?

3. **What is the designed exit path for a Stage 4 user who isn't ready for career guidance?** The safety banner fires correctly, but a user who leaves after the red screen has an unresolved emotional experience with no follow-up hook, no saved safety resource, and no lightweight "나중에 하기" path.
